Plan diff NEW

When the current profile version differs from the last run's, compute added = in_plan(now) − in_plan(run) and removed = in_plan(run) − in_plan(now). Show it on the profile save toast (“+3 tests, −1 test”), on Run setup, and in the out-of-date banner. Removed tests keep their history but leave readiness immediately.

Plain summary per result NEW

Every result carries a one-sentence summary written for a non-developer reviewer, e.g. “Epic refused the patient search (HTTP 403).” The raw observed text (today's evidence string, dict dumps, errno) is only shown under Technical details and in the JSON export — never as the headline, never in the PDF body.

Verdict (one word for the app)

if no complete run:      "Not tested"
elif any blocking Failed (see 03b):
                         "Blocked"
elif any Failed (app):   "Fixes needed"
elif any Needs input (app):
                         "Missing proof"
else:                    "Ready to submit"
if out_of_date: append "· out of date"

Matches ADR-009's top-level verdict. Epic-environment failures show a separate warning, never block the app.

Ordering everywhere (kept)

Failed → Needs input → Not run → Passed → Out of plan; within a group by severity critical → high → medium → low, then ID. “Blocking” = Failed, severity critical or high, and fixable by the user (not Epic's sandbox or Sample data — see 03b).

05Out of date (staleness)

Latest run is out of date when any of:

  1. Profile changed — current profile hash ≠ run's profile hash. Banner shows the plan diff.
  2. Proof changed on an in-plan test — proof sha set ≠ run's snapshot for that test. (Fixes the sticky banner: out-of-plan proof is ignored.)
  3. Test catalog changed — rules_fingerprint differs.
  4. Connection changed — client ID or launch profile differs from the run's.

What the user sees

  • One banner (Overview, Tests, Report) listing the reasons in plain words and one button: Re-run (or Review changes when the plan changed).
  • Per-test “Changed since run” chip on tests whose proof changed.
  • The report shows “Superseded by a newer profile” when opened for an out-of-date run.
  • Readiness numbers stay as measured — never recomputed from un-run changes.

Optional items show exactly which tests they will turn into Needs input, so the user decides with full information.

Run lifecycle NEW

  • Runs execute in the background; the page streams step progress (HTMX polling every 1 s of GET /run/:id/status).
  • Steps shown: Discover Epic → Check sign-in → Read chart data → Find test patient → Write photo → Write note → Validate → Answer review → Score.
  • A step that depends on a failed step is shown “Skipped — because …”, matching the result's Needs input reason.
  • Cancel is allowed while running; partial results are discarded (no half-run in history).
  • Token expiring mid-run → run fails with “Epic sign-in expired during the run”, nothing saved, one-click “Sign in & retry”.
  • Only one run at a time; a second Start shows the running one.

Re-run

  • Full re-run always uses the current profile (fixes the blocker). If the plan changed, the button reads “Review changes & run” and opens Run setup with the diff.
  • Single-test re-run (from test detail) is offered for answer review tests and attested tests (no Epic I/O needed); others say “Needs a full run (uses Epic)”.
  • A single-test re-run creates a new run that copies other results from the previous run and marks them “carried over”.

Sample data

Sample-data runs (mock mode: the smoke test, CLI or /api/run) never replace a real run BUILT: Home, Tests and the test panel show the newest real run. Only when no real run exists yet do they show the newest sample run, under a “Sample data — not a real result” banner; every failure in it is labelled Sample data and none is blocking. Runs lists them as Sample data. Report watermark: planned.

07Proof

Kept from ADR-015

  • Statement ≤ 5,000 characters · Link http(s) only, never fetched · File ≤ 10 MB: text (.txt .log .md .csv .json .yaml .xml .conf .ini .tf, UTF-8), images (png jpg gif webp), pdf.
  • SHA-256 recorded; file always downloaded as attachment.
  • The answer review receives up to 20 MB of images/PDF and 20k chars per text file per test.
  • A statement is an attestation; a bare link is not proof.

Changed NEW

  • All-or-nothing save: validate every part (statement, link, each file) before writing anything; on error keep all inputs and highlight the bad part.
  • Proof only on in-plan tests; out-of-plan tests show existing proof read-only with “Not used — this test isn't in your plan”.
  • Remove asks inline (“Remove proof? Undo”) instead of a browser confirm; undo for 10 s.
  • Adding proof to an AI-review test offers “Re-check this test now”.

08Report, privacy and access

Report content

  • Cover: app, health system, environment, FHIR base, client ID, run date, run ID, tool version, rules fingerprint.
  • Verdict + both numbers.
  • Scope: in plan and out of plan, with reasons.
  • Your app results, then Epic environment as an appendix.
  • Method & limits (e.g. CLIN-005…010 use this tool's sample writes; CLIN-011/012 are attested).
  • Proof index with SHA-256.
  • Passed tests never show “How to fix”.

Privacy (kept)

  • No patient data stored: the test patient is resolved at run time; only booleans and resource ids are kept.
  • Secrets stored as ***set***; token never written to disk.
  • Everything is local to this computer; reports leave only when the user downloads them.

Access (MVP)

  • Single user, single app, local tool (ADR-012). No login.
  • Reviewers receive the PDF/HTML; there is no reviewer account yet.
  • The app switcher in the sidebar is drawn but shows one app until multi-app ships (Spec 4, later).

09Copy & accessibility rules

Copy

  • Use glossary words only (Spec 1). Never show needs_human, [MOCK], Python reprs or errno to users.
  • Test titles in plain language; spec wording as subtitle (e.g. “Clinician can find the right patient” / CLIN-001).
  • Config names (IMAGE_WRITE_RESOURCE) never appear in titles; they appear in Technical details.
  • Jargon gets a dotted underline + definition on hover/focus: SMART, PKCE, scope, fhirUser, MRN, US Core, MyChart, Hyperspace.

Accessibility

  • Test detail drawer: focus trap, Esc closes, focus returns to the row.
  • Tabs use role=tab + aria-selected; tables are real tables with the link in the first cell.
  • Assistant thread aria-live="polite"; run progress announces each finished step.
  • Stepper uses aria-current="step"; status never by colour alone (icon + word).
  • Text contrast ≥ 4.5:1; targets ≥ 44 px on touch.
