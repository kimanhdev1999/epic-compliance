Spec 4 of 4 · Delivery

Release plan: ship clarity first, structure second

Five small releases. Each one is usable on its own and removes a class of confusion. Phase 1 needs no new screens — it fixes words, results and dead ends inside the current layout.

Phase 1 · ~1 week

Say it clearly

  • Glossary rename across UI, export, JSON
  • summary + needs_reason on results; raw text behind Technical details
  • Split readiness: Your app / Epic environment
  • Remove Backend starter; unsupported message
  • HTML 404 + sign-in error pages
  • All-or-nothing proof save; no proof on out-of-plan
  • Staleness: in-plan only
Phase 2 · 1–2 weeks

One source of truth

  • profiles table (versioned)
  • App profile page (1.3) + assistant writes to it (1.2)
  • Data uses always confirmed
  • Re-run uses current profile; plan diff
  • Run stores profile_version
Phase 3 · 1 week

One connection

  • Connect to Epic flow (1.4) used everywhere
  • Callback URL copy + required API list from scopes
  • Persist connection metadata + expiry
  • Test patient “Check” (exactly 1 match)
  • Integrations + Settings → Connections (3.3); drop unused SMART URL fields
Phase 4 · 1–2 weeks

Run & share

  • Run setup pre-flight (1.5)
  • Background run + live progress (2.1)
  • New Overview with verdict + journey (2.2)
  • Report redesign + PDF (3.2)
  • Runs compare (3.1)
  • Single-test re-run for AI tests
Later · ADR-009

Grow the scope

  • Step 2 Verify mode → new “Your app's writes” area in Tests
  • Step 3 App probes → “Your app's backend” connection in 3.3
  • Step 4 Submission pack → Report tab “Evidence pack”
  • Multi-app switcher; reviewer share links
  • ONC test kit results import
